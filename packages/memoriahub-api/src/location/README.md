# location

The location slice of the MemoriaHub domain (RETRO-J10, #624). This cut carries **location grouping** (admin-curated canonical place names that merge many raw reverse-geocoder spellings into one browsable entry per tier) and **location inference** (coordinates for photos without GPS, and the review queue of the guesses).

## Purpose and scope

`LocationGroupResolverService` is THE single component that computes a canonical name: per tier (country, region, locality) the first match wins, **alias** (an admin listed this raw string) beats **radius** (a group's centre and radius contains the item, the smallest radius wins) beats the **raw value verbatim**. With the feature off (`features.locationGrouping` or `LOCATION_GROUPING_ENABLED=false`) it is the identity function, so a non-null raw tier always has a non-null canonical tier. `LocationGroupRebuildHandler` is the server-only `location_group_rebuild` job (30 minutes, two attempts, type string permanent): RESET, then RADIUS, then ALIAS, a handful of set-based statements whatever the library size, and `LocationGroupRebuildService.enqueueRebuild` queues it WITHOUT `skipDedup` so a burst of admin edits collapses into one rebuild. `LocationGroupsService` is the management API (list, values, suggestions, create, update, merge, members). `fold` (alias identity) and `suggestionKey` (suggestion clustering only) are deliberately different normalisations. `haversineKm` and `whereNear` are the shared geometry. `LocationInferenceService` interpolates (two agreeing anchors) or extrapolates (one anchor) from same-device photos that already have coordinates, antimeridian-safe, never anchoring on an inferred coordinate; a two-anchor result within `autoApplyMaxGapMinutes` is applied and recorded as a revertible `auto_applied` suggestion, everything else waits as `pending`. `LocationInferenceHandler` is the server-only `location_inference` job (per-item and circle sweep, 15 minutes, three attempts; a `rerun` reason forces past a rejected suggestion), `LocationInferenceBackfillService` queues one sweep per circle, `LocationSuggestionService` is the review queue (list, accept, reject, revert, rerun) and `LocationInferenceUploadEnrichment` registers the upload fan-out with the media slice (priority 10, photos). The five controllers (`LocationGroupsController`, `LocationGroupsAdminController`, `LocationSuggestionController`, `AdminLocationInferenceController`, `LocationSuggestionRunsController`, the deprecated alias of the review-run API, with their DTO classes) are exported classes over `@MemoriahubAuth` that the host mounts in the modules where its routes belong; the geo providers (offline GeoNames, Nominatim, Google), the `geocode` job and its Google key broker, the geo settings and the forward search still live in `apps/api` and move in a later change (the rest of this issue); the host binds the `GEO_LOCATION_PROVIDER` token the suggestion service calls on accept. Status: experimental until the first published release.

## Entry point

`@marinoscar/memoriahub-api/location` (and `@marinoscar/memoriahub-api/location/testing` for the conformance kit). It imports the `ports`, `core` and `media` slices through their `index.ts` and nothing else of the package.

## Peer dependencies

`@nestjs/common`, `@nestjs/schedule`, `@nestjs/swagger`, `nestjs-zod` and `@marinoscar/memoriahub-contract` (the location wire schemas and the level vocabulary).

## Configuration

`LocationModule.forRoot()` (grouping; the options object is reserved and empty) and `LocationInferenceModule.forRoot({ geoProviderImports })` (inference; the host passes the module that provides and exports `GEO_LOCATION_PROVIDER`). Import each once in the host and re-export it from the host's own module; the first `forRoot()` call wins. The slice reads the `locationGrouping` system settings namespace (`radiusCaptureEnabled`, `maxRadiusKm`, `suggestionMinItems`) and `features.locationGrouping` through the settings port, and the kill switch `LOCATION_GROUPING_ENABLED` from the environment through the `isFeatureEnabled` helper of `core`. The all-scopes sweep of the rebuild reads `MEMORIAHUB_ACCESS.allScopeIds()`. Inference reads `features.locationInference` (kill switch `LOCATION_INFERENCE_ENABLED`) and the `locationInference` namespace (`maxGapMinutes`, `maxExtrapolationGapMinutes`, `autoApplyMaxGapMinutes`, `requireSameDevice`, `maxAnchorDistanceKm`, `maxImpliedSpeedKmh`, `bulkAcceptThreshold`).

## Extension-point catalog

`GEO_LOCATION_PROVIDER` (the reverse geocoder the host binds) and the media slice's `UploadEnrichmentRegistry` (this slice registers `location_inference`). The slice registers two job handlers through `MEMORIAHUB_JOBS` and exposes the resolver, the rebuild enqueue helper and the management service to the host. Every host write path that touches a `geo_canonical_*` column must go through `LocationGroupResolverService`. `describeLocationSliceConformance` (`./location/testing`) proves alias-beats-radius, the smallest-radius rule, the identity behaviour with the feature off and the enqueue rule of the rebuild.
