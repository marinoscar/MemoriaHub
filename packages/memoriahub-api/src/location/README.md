# location

The location slice of the MemoriaHub domain (RETRO-J10, #624). It carries **location grouping** (admin-curated canonical place names that merge many raw reverse-geocoder spellings into one browsable entry per tier) **location inference** (coordinates for photos without GPS, and the review queue of the guesses) and the **geo** half: reverse and forward geocoding, the geo administration and the `geocode` job.

## Purpose and scope

`LocationGroupResolverService` is THE single component that computes a canonical name: per tier (country, region, locality) the first match wins, **alias** (an admin listed this raw string) beats **radius** (a group's centre and radius contains the item, the smallest radius wins) beats the **raw value verbatim**. With the feature off (`features.locationGrouping` or `LOCATION_GROUPING_ENABLED=false`) it is the identity function, so a non-null raw tier always has a non-null canonical tier. `LocationGroupRebuildHandler` is the server-only `location_group_rebuild` job (30 minutes, two attempts, type string permanent): RESET, then RADIUS, then ALIAS, a handful of set-based statements whatever the library size, and `LocationGroupRebuildService.enqueueRebuild` queues it WITHOUT `skipDedup` so a burst of admin edits collapses into one rebuild. `LocationGroupsService` is the management API (list, values, suggestions, create, update, merge, members). `fold` (alias identity) and `suggestionKey` (suggestion clustering only) are deliberately different normalisations. `haversineKm` and `whereNear` are the shared geometry. `LocationInferenceService` interpolates (two agreeing anchors) or extrapolates (one anchor) from same-device photos that already have coordinates, antimeridian-safe, never anchoring on an inferred coordinate; a two-anchor result within `autoApplyMaxGapMinutes` is applied and recorded as a revertible `auto_applied` suggestion, everything else waits as `pending`. `LocationInferenceHandler` is the server-only `location_inference` job (per-item and circle sweep, 15 minutes, three attempts; a `rerun` reason forces past a rejected suggestion), `LocationInferenceBackfillService` queues one sweep per circle, `LocationSuggestionService` is the review queue (list, accept, reject, revert, rerun) and `LocationInferenceUploadEnrichment` registers the upload fan-out with the media slice (priority 10, photos). The five controllers (`LocationGroupsController`, `LocationGroupsAdminController`, `LocationSuggestionController`, `AdminLocationInferenceController`, `LocationSuggestionRunsController`, the deprecated alias of the review-run API, with their DTO classes) are exported classes over `@MemoriahubAuth` that the host mounts in the modules where its routes belong; the three reverse providers (`OfflineGeoLocationProvider`, `NominatimGeoLocationProvider`, `GoogleGeoLocationProvider`), `GeoLocationService` (the active provider from `geo.reverseProvider`, else `GEO_PROVIDER`, else offline; Google falls back to offline without an enabled key), `DelegatingGeoLocationProvider` (what the `GEO_LOCATION_PROVIDER` token resolves to, so an administrator switches providers without a restart), `ForwardGeocodeService` (place search by typed text, only the query leaves the server, gated by `geo.forwardSearchEnabled`), `GeoGoogleCredentialResolver` and `GeoSettingsService` (the Google key is the secret `geo_provider/google` through the secrets port and is write-only: no route returns it, no log line or error carries it; its non-secret half is the `geo` namespace), `GeocodeBackfillService` and the `geocode` job (`GeocodeHandler`: node-eligible, 60 seconds, three attempts, throttle bucket `geocode`, with `GoogleGeocodeKeyBroker` delivering the key only through the per-job secret; a provider quota signal is a `MemoriahubRateLimitError`, so the job is deferred and its status stays `pending`) are in the slice, and three more controllers (`GeoSettingsController`, `GeocodeAdminController`, `GeocodeMediaController`, with `UpsertGeoCredentialDto`, `SetGeoReverseProviderDto`, `TestGeoProviderDto` and `BackfillGeoDto`) are exported classes the host mounts. `local-reverse-geocoder` (the GeoNames dataset behind the offline provider) is an optional peer, loaded on first use. Status: experimental until the first published release.

`fold`, `GEO_CLEAR_COLUMNS`, `geoResultToMediaColumns` and `applyLocation` are defined in the `media` slice (its gallery service writes locations and `location` depends on `media`) and re-exported here, so their public names did not change.

## Entry point

`@marinoscar/memoriahub-api/location` (and `@marinoscar/memoriahub-api/location/testing` for the conformance kit). It imports the `ports`, `core` and `media` slices through their `index.ts` and nothing else of the package.

## Peer dependencies

`@nestjs/common`, `@nestjs/schedule`, `@nestjs/swagger`, `nestjs-zod`, `@marinoscar/memoriahub-contract` (the location wire schemas and the level vocabulary), `@marinoscar/memoriahub-compute` (the geocode response mappers, the node result schema and the rate-limit helpers) and, optional, `local-reverse-geocoder`.

## Configuration

`LocationModule.forRoot()` (grouping and geo; the options object is reserved and empty; it provides and exports `GEO_LOCATION_PROVIDER`) and `LocationInferenceModule.forRoot()` (inference). Import each once in the host and re-export it from the host's own module; the first `forRoot()` call wins. The slice reads the `geo` namespace (`reverseProvider`, `forwardSearchEnabled`, `google.enabled`, `google.baseUrl`), the environment fallbacks `GEO_PROVIDER`, `GEO_FORWARD_PROVIDER`, `GEO_FORWARD_SEARCH_ENABLED`, `NOMINATIM_BASE_URL`, `GOOGLE_MAPS_API_KEY` and `GEONAMES_CACHE_DIR` (where they always were), the `locationGrouping` system settings namespace (`radiusCaptureEnabled`, `maxRadiusKm`, `suggestionMinItems`) and `features.locationGrouping` through the settings port, and the kill switch `LOCATION_GROUPING_ENABLED` from the environment through the `isFeatureEnabled` helper of `core`. The all-scopes sweep of the rebuild reads `MEMORIAHUB_ACCESS.allScopeIds()`. Inference reads `features.locationInference` (kill switch `LOCATION_INFERENCE_ENABLED`) and the `locationInference` namespace (`maxGapMinutes`, `maxExtrapolationGapMinutes`, `autoApplyMaxGapMinutes`, `requireSameDevice`, `maxAnchorDistanceKm`, `maxImpliedSpeedKmh`, `bulkAcceptThreshold`).

## Extension-point catalog

`GEO_LOCATION_PROVIDER` (the active reverse geocoder; the slice binds it, a host may override it) and the media slice's `UploadEnrichmentRegistry` (this slice registers `location_inference`). The slice registers two job handlers through `MEMORIAHUB_JOBS` and exposes the resolver, the rebuild enqueue helper and the management service to the host. Every host write path that touches a `geo_canonical_*` column must go through `LocationGroupResolverService`. `describeLocationSliceConformance` (`./location/testing`) proves alias-beats-radius, the smallest-radius rule, the identity behaviour with the feature off and the enqueue rule of the rebuild.

**Diagnostics (RETRO-J10, #624).** The slice registers the `memoriahub.geo.reverse-provider` check (`GeoReverseProviderDoctorCheck`: one reverse lookup through the active provider) through the `MEMORIAHUB_DOCTOR` port from `forRoot()`. Read-only; the id and the statuses are the ones the app declared before the move.
