# Local exceptions to the platform

Every place where MemoriaHub deviates from `@marinoscar/platform-*` on purpose, and the issue that removes it. Introduced by RETRO-A1 (#568, epic [#555](https://github.com/marinoscar/MemoriaHub/issues/555)). An exception without a row here is a bug.

A4 (#579) added the first shim row; A5 (#587) added the database deviations and the `DefaultOrgId` shim; B2 (#611) removed the avatar deviation, the platform-schema stub and the host-access delegation, and added the identity rows below. B4 (#617) added the legacy secret cipher and the legacy face/geo credential tables. B3 (#614) removed the host-core settings port (`host-core-ports.module.ts`) and the `getSettings({ readOnly })` shim, and added the settings rows. C1 (#575) moved the queue onto the platform jobs slice: it removed the `IDENTITY_JOBS` row and the temporary `jobs` namespace, narrowed the `legacy-platform-tables` deviation, and added the jobs rows below. D4 (#580) moved database backup onto the platform db-backup slice: it removed the temporary `databaseBackup` namespace and the db-backup cron from the `cron-enqueue-only` debt, and added the db-backup rows below. A5b (#653) renamed the legacy storage-migration tables out of the way of platform `0042`, widened the `legacy-platform-tables` deviation and added the storage-migration row below. D3 (#576) moved notifications onto the platform notifications slice (platform 0.1.0-next.27): it removed the `AppEmailSender`, `DB_BACKUP_NOTIFIER`, `IDENTITY_NOTIFIER`, C8 notification-retention and phase-1 rows, the temporary `notifications` namespaces and the settings subclasses' dismiss-on-disable, and added the notifications rows below. T2 (#625) mounted the platform telemetry slice and added the disabled-assistant and conformance-check-5 rows. D1 (#563) moved object storage onto the platform storage slice (platform 0.1.0-next.28, whose multi-provider seams, EAB #1124/#1121, it uses: per-driver secrets, the `platformGrants` widening, optional processors, `cacheControl`, bulk delete and size, the 415 part parser, the backup target's recorded location): it removed the `SETTINGS_DATA`, `DB_BACKUP_SYSTEM_DATA`, legacy `db-backups/` prefix, `jobWriteScope`, `thumbnail_repair` and `AI_OBJECT_STORE` rows and the temporary `storage` namespace, turned `on-event-no-io` on, re-pointed `MemoriaHubBackupTarget`, and added the storage rows below; merged after H1, it also removed H1's `USER_DATA_DB` row (the port now rides `PrismaSystemService`). H5 (#609) mounted the platform alerts slice and added the four alerts rows. H1 (#591) mounted the platform user-data slice and added the four user-data rows. H4 (#603) mounted the platform webhooks slice, added the `WEBHOOKS_SYSTEM_PRISMA` row and removed H5's "Alerts without the webhook port" row (`ALERTS_WEBHOOK_EMITTER` is bound).

## How to use this page

- **A shim in code** carries the comment `// PLATFORM-ADOPTION-SHIM(<issue>)`, where `<issue>` is the issue that removes it. List them all with `grep -rn "PLATFORM-ADOPTION-SHIM" apps/api/src apps/web/src apps/cli/src`.
- **A deviation in the database** is an entry under `deviations` in `apps/api/prisma/platform.lock` (created by A5).
- **The PR that removes an exception deletes its row here.** It also removes the marker and the lock deviation it names.
- A new exception adds a row in the same PR, with an issue that removes it. If no issue exists, file one.
- Platform code is never edited in this repository. A missing seam is a `seam_request.yml` in EnterpriseAppBase (app = MemoriaHub); if the work cannot wait, eject with a shim and a row below.

How the baseline treats the deviations: `docs/runbooks/database-baseline.md` in EnterpriseAppBase.

## Standing constraints

Rules that hold for the whole program and are not exceptions:

- An installed migration is never edited or renamed; comments inside `migration.sql` count.
- Raw-SQL partial unique indexes (`jobs_active_dedup_uniq_idx`, `database_backup_runs_active_uniq_idx`, `notifications_review_queue_live_uniq_idx`, `android_app_releases_one_current_uniq_idx`, and the others the platform lists in `raw-sql-indexes.json`) are intentional schema drift and are never replaced by `@unique`.
- Job `type` strings, notification keys, webhook event keys and storage key prefixes are permanent.
- Generated files (`prisma/schema/`, generated `infra/`, `.env.example`) are never hand-edited.
- At most one open PR carries a migration at a time (`migration-lock`).
