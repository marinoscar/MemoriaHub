MemoriaHub · Information architecture · August 2026

The sidebar is a feature list. It should be a map.

The drawer has 22 rows because every feature that shipped earned one. That is an accurate picture of the codebase and a poor picture of what anyone is trying to do. This proposal cuts primary navigation to four destinations and gives phone, tablet, and desktop three genuinely different treatments instead of one drawer stretched across all of them.

01 — Diagnosis

Half the drawer is already on screen

Item count is the symptom, not the disease. The disease is that the drawer accumulated one row per shipped feature, so it now mirrors the API surface rather than anyone's mental model — and eleven of those rows lead somewhere the user can already reach without opening the drawer at all.

The four admin shortcuts are the clearest case: they are an arbitrary sample of a 25-page hub, hoisted into global navigation. That does not scale — the next admin page shipped has no principled reason to be excluded, and no room to be included.

There is a second, structural problem underneath. MemoriaHub is self-hosted, so the same person is both the family photo browser and the system operator. Those are two different jobs with two different cadences — daily versus monthly — and right now they compete for the same 240 pixels. Every other photo app avoids this by not having an operator at all. The fix is to separate the modes, not to keep re-ranking rows within one list.

02 — What the field settled on

Four findings that shaped this

Google Photos went to three tabs

The year-long redesign collapsed navigation to Photos, Collections, Search. People & pets, Places, Albums, Documents and Moments all moved into Collections; Create and the Updates bell moved to the top bar. They accepted the extra tap explicitly, in exchange for organized groupings over a flat list.

9to5google, Mar 2025

Material 3 deprecated the drawer

In the M3 Expressive update the navigation drawer is deprecated, replaced by an expanded navigation rail — same functionality, adapts far better across window size classes. A rail is always visible; a drawer costs a tap before any navigation can begin.

m3.material.io · 9to5google, May 2025

Apple showed the failure mode

iOS 18 Photos removed the tab bar for one scrolling page. The backlash was immediate — “Albums particularly difficult to reach” — and Apple partially rolled back in 18.1/18.2, adding Customize & Reorder. Consolidation works; deleting stable destinations does not.

MacRumors · TechRadar, Nov–Dec 2024

Three to five, and no more

Bottom tab navigation is the settled mobile standard, with 3–5 destinations the consistent recommendation and odd counts giving better visual rhythm. Four is the ceiling that still leaves each label readable at 360 px.

Mobile navigation UX surveys, 2025–26

The through-line: every serious photo app consolidated into a small set of stable destinations plus one rich hub — and the one that instead removed destinations entirely had to reverse course. This proposal sits deliberately on the Google side of that line, with Apple's correction (user pinning) built in from the start rather than bolted on after complaints.

03 — The recommendation

Four destinations, two modes

Everything the user does falls into four verbs: look at the timeline, browse something curated, find one specific thing, and decide on what the system has queued up for them. That last one is MemoriaHub's genuine differentiator — unlike Google Photos, this app generates work: bursts to resolve, duplicates to merge, locations to confirm, enhancements to approve. It currently costs six drawer rows. It should cost one badged destination.

One implementation note worth flagging early: the Review badge needs no new backend. GET /api/media/review-counts already returns exactly the four integers in a single counts-only request — it was built for the sidebar's enhancements badge. The aggregate is a sum of what you already fetch.

04 — Ranked by payoff

Four moves, largest first

1

Collapse the review queues into one badged destination

Six rows become one. These queues are empty most of the time and full right after an import — a burst of work, not a permanent fixture. A single badged inbox matches that rhythm; six always-present rows do not.

−5 rows
2

Move the admin surface into its own mode

Console gets its own rail at /admin, reached from the avatar menu. The library nav stops carrying four arbitrary operator shortcuts, and the 25-page hub finally has somewhere to grow.

−5 rows
3

Fold browse targets into Collections

Albums, People, Places, Map, Memories, Archive and Trash become a visual hub with cover thumbnails and counts — not a text list. This is the move that buys the extra tap, so the hub has to be worth arriving at.

−6 rows
4

Give the top bar what belongs to the top bar

Circle chip, upload, bell, avatar. Removing Circles, Notifications and User Settings from the drawer costs nothing — all three are one tap away in chrome that never scrolls off.

−3 rows

06 — The second mode

Console is a place, not five shortcuts

Entering /admin swaps the rail's contents rather than the app shell: Overview, Jobs, Nodes, Storage, Backup, Sharing, Settings, Doctor. The circle chip stays, the search pill goes, and a persistent “← Back to library” sits at the top of the rail so the mode is always obviously escapable.

This is the cheapest structural change in the whole proposal — it's a conditional on location.pathname.startsWith('/admin') inside one component, and the SettingsHubPage that would populate it already exists. It permanently removes five rows and gives the admin surface room to grow past 25 pages without touching global navigation again.

07 — What this costs

Three honest objections

People, Map and Albums each cost one more tap.

Real, and unavoidable — it's the same trade Google made deliberately. It's only worth it if Collections is visually rich enough to be a destination in its own right: cover thumbnails, live counts, recently-viewed first. If Collections ships as a text list, this proposal makes the app worse. Desktop pinning and the context pane recover the cost entirely for power users.

Queues get harder to notice.

Mitigated three ways that already exist: the aggregate badge on Review, the review-queue notifications the reconcile task writes hourly, and the Home banners. If anything the current design under-signals — six quiet rows read as furniture, one badge reads as work.

Don't hide Review when the count is zero.

Tempting, and wrong. Navigation that changes shape is worse than navigation that's slightly long — users can't find a feature they know exists, and can't build muscle memory against a moving target. Keep the destination, drop the badge.

08 — Sequencing

Shippable in four increments

Ordered so each phase stands alone and is independently revertible. Phase 1 alone removes eight rows without a single new page.

Phase 1 · deletions
Console mode + drop the duplicated rows

Conditional rail at /admin; remove Circles, Notifications, User Settings and the four admin shortcuts. Add the circle chip to the top bar. No new routes, no new API. −8 rows.

Phase 2 · one new page
The Review hub

/review with six tabs wrapping the pages that already exist, plus the aggregate badge off review-counts. −5 rows.

Phase 3 · one new page
The Collections hub

/collections as a visual grid over Albums, People, Places, Memories, Map, Favorites, Archive, Trash. The riskiest phase — it's the one that spends the extra tap. −6 rows.

Phase 4 · chrome
Rail, bottom bar, pinning

Replace the drawer with a collapsed rail at md and an expanded rail at lg; phone bottom bar goes to four items and the drawer is deleted. Add user_settings.navigation.pinned.
